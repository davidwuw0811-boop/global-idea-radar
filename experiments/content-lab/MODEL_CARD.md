# 模型说明

名称：Malachi Content Lab。版本：0.1.0。类型：编辑决策框架、规则检查器、提示词任务包和观察性复盘工具。

## 已实现

- 用 JSON 记录草稿、读者任务、主张证据与读者交付承诺。
- 检查事实表达与批注矛盾、未完成交付承诺、过时批注、缺失评分。
- 输出可交给人工或任意语言模型的编辑任务包。
- 计算每千次曝光的各类行为密度，缺失值不填零。
- 在同作者、同平台、同格式、同题材、同篇幅档、同窗口、同分发类型与同计数口径中，比较更早帖子中位数。

## 未实现

没有训练语言模型或爆款预测器，没有学习权重，没有 X 账号连接，没有自动写稿和发布，没有后台定时采集，没有 DSPy 或 Promptfoo 集成。现有 Python 命令不联网，也不产生模型 API 费用。brief 生成的是任务文字，须另交人工或已有模型执行。

## 适用与限制

适合中文商业观察、AI 普及和创意案例的编辑讨论；不声称覆盖所有创作体裁。示例数据全部为虚构，用来检查程序行为；它们不得用于证明传播效果。

人工评分可能带有偏见。若以后用 LLM 批评 LLM，先盲评两个版本并交换顺序，再由作者处理分歧。多个模型一致也不是读者验证，更不能证明事实。

views 表示次数，可能包含重复阅读，也可能含推广。公开页面的帖子曝光、文章阅读、视频播放必须分开。收藏、关注和询盘数据看不到就留空。按曝光算出的数值不是独立读者转化率。

历史对照并非随机实验。题材热度、作者粉丝规模、大号转发、发布时间、图片和外链等仍会混杂。min_baseline=5 只是拒绝过小对照组的显示规则，没有统计效力承诺。

## 下一阶段

建议先整理约 30 篇本人文章的可用指标，再选 40—60 篇外部参考，外部样本同时包括普通和低表现作品。这是启动规模，不是有效预测所需样本量。先保证指标、时间窗口和来源一致。

每篇确定主要目标：触达、实用反馈或业务询盘。新内容在发布后 24 小时、72 小时保存快照；旧截图年龄未知的，只保留原始记录，不与固定窗口混算。

有稳定数据后才试 Promptfoo 比较提示词；再考虑 DSPy 优化或小型排序器。按时间拆分训练与测试，按作者或近重复内容分组，防止泄漏。先打败“账号近期同类中位数”基线，再谈预测。不在同一批样本上选规则又宣称验证有效。

## 数据与公开范围

仓库包含自写代码、工作方法、虚构示例和来源链接。自己的未发布文章、第三方全文、截图、账号凭据、客户资料与经营记录放在本地 private/，该目录已排除版本管理。公开框架与私有案例库分开维护。
